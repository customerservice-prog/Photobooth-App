# Coded event template collections

This release implements templates in app/lib/templates, not generated presentation-board images. There are six event modules and eighteen globally unique template IDs. Wedding and Birthday route through the preserved Atelier renderer so their approved artwork is not changed. Mitzvah, Graduation, Corporate and Other each have three new authored render functions, photo geometries, decorations and text treatments. The actual controls remain the existing calm three-card gallery; no animations are added.

registry.mjs owns canonical IDs, per-event resolution and catalog metadata. fields.mjs owns the setup field schema; EventSetup and composeEventConfig read it. render.mjs is the entry point used through the backwards-compatible keepsake-designs facade by PrintCard and the existing finished-JPEG exporter. Existing ivory/blush/champagne selections are preserved and mapped to canonical IDs; saved defaults retain both forms. Unknown and cross-event IDs fall back inside the selected event rather than rendering another event's design. No customer data is migrated or deleted.

The twelve new collections are: Timeless Tradition / Modern Mazel / Celebration Mosaic; Honors Edit / Confetti Finish / Future Forward; Executive Modern / Evening Gala / Summit Clean; Celebration Blooms / Evening Soirée / Confetti Moment. Each has a distinct composition, not a shared frame recolored. Brand tagline and optional mitzvah motifs are now real setup fields. Specific religious motifs are optional and default to geometric artwork. Existing name, caption and host aliases are supported without discarding the saved field names.

The public /api/template-catalog endpoint returns design metadata only, never guest configuration, photos, delivery details or secrets. /designs uses fictional sample details and no real guest images. The same selected artwork is used for print and 1200x1800 JPEG download; any configured direct delivery receives that finished file. This release does not supply sender credentials, send real messages, certify Guided Access, or verify physical Canon output. Gold and texture are printable color effects, not real foil or embossing.

Verification is recorded by the Event template collections workflow. The proof runs the full test suite, production Next build, and actual gallery/export interactions in Chromium and WebKit on localhost. It does not claim the desktop WebKit test is a physical iPad test. Proof images use a separate illustrative stock photo only in the isolated browser session. No user photos or contacts are used and delivery POSTs are blocked. File-size, dimensions, names, distinct IDs, selected print structure and screen overflow are explicitly checked. Final pass/fail must be read from the workflow result, not inferred from this document.
